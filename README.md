# AgentGuard

个人自用的 macOS 权限管控工具：给命令行工具和 Agent 设定能读写哪些目录、能执行哪些程序、能连哪些本机端口，所有扩大权限的变更都要经本人系统认证。

> **状态：** 核心逻辑已有完整单元测试；macOS 集成部分（沙箱是否真正拦截、XPC、授权服务、eslogger）尚未在真机验证。见 [docs/M0-CHECKLIST.md](docs/M0-CHECKLIST.md)。

## 组成

| 组件 | 作用 | 运行身份 |
| --- | --- | --- |
| `AgentGuard.app` | 菜单栏 App：按程序查看状态和实际权限、处理被阻止的访问、整理启动入口、设置与卸载 | 当前用户 |
| `guard` | `guard run <配置档> -- <命令>`：以已批准的配置档启动命令；`guard status` | 当前用户 |
| `agentguard-launcher` | 被接管的 LaunchAgent 用它进入沙箱后启动目标 | 当前用户 |
| `agentguard-helper` | 唯一的特权组件：保存修订、生成规则、校验调用方与系统认证、跟踪运行实例、采集行为 | root |

所有判断都在 `GuardCore` 中完成（不依赖系统接口，可在 Linux 上测试），`GuardPlatform` 和各可执行文件只负责调用 macOS 接口。

## 安全模型

- **默认拒绝**：未列出的访问一律被沙箱拒绝（“记录更多活动”也一样，只是额外记录成功的文件访问）；任何一步失败都保持停止，不退回无限制运行。
- **扩权要认证**：Helper 先生成精确差异，App 展示后用系统认证（每次一个新的授权，权利名绑定到这一次变更）；Helper 校验调用方 cdhash、uid、基础修订号后才写入。收紧权限不需要认证。
- **受管进程不能扩权**：规则固定拒绝连接 Helper 的 XPC 服务、拒绝写入配置与发行目录、App 包和 LaunchAgents 目录；即使绕过，Helper 也会拒绝来自受管进程树的请求。
- **撤销以旧实例退出为准**：只有使用旧修订的进程及其后代全部退出，才显示“已生效”。
- **生效以外部核对为准**：受管进程不能自己报告“已生效”。Helper 用 `sandbox_check` 从外部核对运行中的进程：默认拒绝、Helper 隔离、受保护目录，以及每条文件授权的读写结果都与配置一致，才显示“已生效”；核对不通过时列出具体原因。
- **运行记录不在受管程序可写的位置**：实例记录保存在配置目录（沙箱内只读、root 所有），Helper 重启后重新核对沙箱，不沿用旧结论。
- **观察不等于完整审计**：界面显示“已观测行为”和采集器缺口；没有记录只表示未观测到。被阻止的访问（有沙箱拒绝记录）和权限建议（观察到但没有被阻止）分开列出，只有前者可以“保持阻止”。
- **实际权限按来源合并**：权限页合并你添加的授权、推荐权限组、程序启动所需和迁移来的旧规则，标出每条的来源与覆盖关系；存在无法核对的旧规则时明确标为“列表可能不完整”。撤回时一并处理只在该位置之内的授权，并点名仍保留访问的其他来源。
- **停止以实际退出为准**：停止、重启、移除和卸载都会报告哪些进程确认退出、哪些被强制结束、哪些仍在运行或没有身份记录；Helper 重启后恢复的运行副本会按父进程找回子进程，但仍标为“跟踪不完整”，直到重启。

文件授权支持通配路径，例如 `~/.claude*.jsonl`、`~/.claude/projects/**/*.jsonl`：`*` 匹配一级名称中的任意字符，`?` 匹配一个字符，单独一级的 `**` 匹配任意层目录。通配符第一次出现之前的部分按普通路径规范化，之后的部分不解析符号链接；紧跟在根目录或主目录下的纯通配（如 `~/*`）会被拒绝，受保护目录的检查同样适用。

只保证**通过 AgentGuard 入口启动**的进程及其子进程受限；同一程序从其他入口启动时只能被发现和提醒。“整理现有安装”列出启动同一程序文件的其他启动项（只按程序路径匹配，不按名称），可以备份后停用、随时恢复。

| 操作 | 结果 |
| --- | --- |
| 关闭窗口 | 隐藏窗口，菜单栏、受管程序和后台限制继续运行 |
| 退出 AgentGuard | 退出窗口和菜单栏；受管程序和后台限制继续运行，不改变登录启动设置 |
| 停止本次运行 | 停止受管副本及子进程并报告未确认的部分；本次登录不再自动拉起，以后登录按原设置 |
| 关闭程序登录自启 | 只影响以后的登录，不停止当前运行 |
| 移除某个程序的保护 | 先停止受管副本，再删除权限和启动项；恢复原启动方式须明确选择 |
| 卸载 AgentGuard | 停止全部受管程序，移除启动项、采集器和 Helper；权限设置、备份和工作数据保留 |

## 开发

```sh
scripts/test.sh                 # 运行全部测试（Linux 或 macOS）
scripts/build-app.sh            # 在 macOS 上构建 build/AgentGuard.zip（ad-hoc 签名）
```

构建出的 App 放在 `build/stage.noindex/`，Spotlight 不索引这个目录，过程版本不会出现在应用搜索里；只把 `build/AgentGuard.zip` 解压到“应用程序”使用。每个 Pull Request 都会在 macOS 上编译、测试和打包。

测试约定见 [docs/TESTING.md](docs/TESTING.md)。

## 发布

合并到 `main` 时，GitHub Actions 在 macOS 上运行测试、打包，并创建预发布版本 `v<VERSION>-build.<序号>`。`main` 受保护，只能通过 Pull Request 合并。

## 安装

1. 从 Releases 下载 `AgentGuard.zip`，解压后拖进“应用程序”，运行 `xattr -cr /Applications/AgentGuard.app`（未公证）。
2. 打开 App →“安装 Helper”，在“系统设置 > 通用 > 登录项 > 允许在后台”中允许 AgentGuard。
   第一次点“安装 Helper”时 macOS 会拒绝启动尚未允许的后台项目，这是正常流程；允许后 App 会自动连上。
3. 在“隐私与安全性 > 完全磁盘访问”中添加 `/Library/PrivilegedHelperTools/com.lsclpangpang.agentguard.collector`（选择窗口里按 ⌘⇧G 输入路径），然后运行 `sudo launchctl kickstart -k system/com.lsclpangpang.agentguard.collector`。eslogger 由这个独立采集器进程启动，系统按它判断授权；它装在 App 包外，App 重新签名不会让授权失效。不授权只能看到沙箱拒绝记录，看不到进程生命周期。
4. 点工具栏的 +“添加程序”：选择程序、选择项目文件夹、查看权限摘要，保存后启动。命令行工具会给出可以直接复制运行的完整命令；被阻止的访问在“最近活动”中处理。

遇到任务已完成却一直等待退出时，检查“任务结束与取消”中的“管理本次运行的进程”。
这项权限只控制同一次受保护运行中的进程，启用需要系统认证，保存后重启目标程序生效。
维护时也可用已安装 App 的专用命令 `/Applications/AgentGuard.app/Contents/MacOS/AgentGuard --repair-process-control <配置档> --restart`；
它会先更新后台服务，再读取最新配置并为这一项权限发起独立认证，认证通过后重启目标程序。重启会结束该程序当前运行的会话。
