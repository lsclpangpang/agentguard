新增 `guard diagnose-read <配置档> <绝对路径> [--json]` 只查询当前进程的正文读取、属性查询、写入边界，不打开目标。Helper 对精确 ProcessKey 独立核对完整系统出生时间并在核验前后匹配；CLI 再次核对前后完整出生时间和保护状态。旧 Helper 缺字段、退出或 PID 复用时不输出确认的访问结论；路径缺失和系统未答复分别保留，不当作拒绝。该命令不授予权限，也不证明历史调用实际消耗了内容字节。

## 实现范围

| 部分 | 已实现的行为 |
| --- | --- |
| 事件接入 | 在确认受管归属后、映射权限建议前逐条保存事件；保留原始动作、目标、结果依据、来源、进程与运行身份、当时的实际修订。重复访问分别保存；rename 的两个路径有共同来源事件与不同子序号。 |
| 采集边界 | 文件订阅条件独立于保护模式。采集队列与写入队列共用 8 MiB／10000 条预算，批次最多 256 条；未完成行最多 1 MiB。溢出、断连及来源序号缺口明确报告，不扩大允许项。 |
| 保存 | Helper 写入 JSONL 分段；受保护目录 0700、文件 0600。文件操作拒绝软链接、路径越界、错误所有者、错误权限和硬链接。恢复未封段的完整行，中间损坏段隔离，未知格式保留并计入容量。 |
| 清理 | 默认保留 7 天；每程序 256 MiB、全局 512 MiB；16 MiB 或 1 小时轮转；每 15 分钟以及启动、轮转、容量不足时清理。达到容量上限后降至 80%；可用磁盘低于 1 GiB 时提前清理，仍不足则暂停写入并报告。 |
| 查询界面 | 时间与结果筛选、200 条分页、单页内存、有界返回位置；显示写入／同步进度、排队、覆盖范围、缺口与错误。清理使位置失效时要求显式刷新。旧 Helper 只显示临时缓存并提示更新。 |
| 导出 | 固定查询范围，分块读取已写入的记录；首行说明范围、覆盖、已知缺口及截断边界。以 0600 临时文件写入，失败或取消保留原目标文件，完成后原子替换。导出文件由用户管理。 |
| 清空与设置 | 独立日志开关不改权限修订；清空以采集入口与写入序号屏障分开新旧记录，避免旧排队记录重新出现。清空操作在处理历史中留摘要。日志接口仅向通过既有校验的 App 开放。 |

这证明旧实现存在可复现的传输缺陷，不能证明现场每条 `invalidWire` 都由它导致，更不能把实验损坏比例当作现场丢失率。随 build 75 打包的新 Collector 已有串行非阻塞写入代码，但安装中的稳定二进制未替换，因此不能把随包修复写成现场已生效；该修复本身也不能解决 eslogger 全量序列化负载。可重跑源码、参数、计数与完整限制见同目录 `malformed-transport-probe.swift`、`malformed-transport-probe-result.json`、`malformed-transport-probe.md`。
