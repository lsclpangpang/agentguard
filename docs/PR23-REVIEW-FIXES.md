# PR #23 审查问题修复

本次修复针对权限说明、撤权结果、进程身份和后台服务维护的八项审查问题。

1. 通配规则比较完整匹配范围，拒绝相互冲突的只读/读写规则；保留只读父目录搭配显式可写子目录的用法。权限概览和撤权检查也计算通配范围重叠。
2. 旧规则的网络、执行权限及未展开的系统基础规则明确标为待核对。关闭结构化开关或删除执行授权时，确认页列出仍保留的相关旧规则。
3. 恢复进程树前检查每个已有进程的 PID 和启动时间，清除失效归属；新增子进程必须与同次进程快照中的启动时间一致。
4. 已知进程退出不会消除追踪缺失。停止结果和修订状态继续报告未确认；受保护的实例记录跨 Helper 重启保留，仅在完整观察到退出或确认系统重启后清除。
5. 卸载暂停轮询、延迟修复和手动修复任务，并使旧回调失效。暂停状态跨 App 重启保留；失败时报告未完成，用户手动修复才恢复维护。
6. 复制到终端的命令采用独立的 shell 参数引用，不会展开路径或参数里的命令替换、变量和运算符。
7. 手动修复识别可连接但协议较旧的 Helper，等待旧服务退出后重新登记，并继续等待新协议响应。协议版本提升到 3。
8. 新建后台脚本配置保存解析后的解释器绝对路径与脚本参数，不依赖 launchd 的 PATH。保留脚本身份，避免把其他使用同一解释器的程序误认作受管对象。含环境修改或未支持展开的 shebang 会要求手动配置。

## 本机保护核验误报修复

build 63 的目录核验使用了不存在的 `.agentguard-probe` 子路径。macOS 的
`sandbox_check` 对不存在的路径可能返回拒绝，造成已授权目录整批误报；不存在的
未授权路径也不能作为“默认拒绝已生效”的证据。

- 目录授权与内置保护检查改用真实目录；默认拒绝检查优先选择授权范围外的现有系统目录。
- 路径查询前后检查对象是否存在、是否发生替换。缺失或查询失败单独报告“暂未核验”，
  不计作访问拒绝，也不计作边界验证通过。
- 每五秒重新核验运行实例，清除过时的成功或失败结论；历史仅记录结论变化。
- 界面区分权限差异和暂未核验，不再把访问受限直接表述成程序没有受到保护。
  启动流程不再展示空的停止结果，已有核验结果时及时结束启动等待。
- Helper 协议提升到 4，确保 App 不会使用旧核验实现。

`scripts/test.sh`：490 项通过，1 项登录启动测试保持显式跳过。
新增真实 macOS 子进程测试：先执行允许创建、只读写入拒绝、禁止读取，再从父进程查询
相同对象；确认缺失文件不会误判为允许或拒绝，文件出现后可以重新核验通过。
`BUILD_NUMBER=64 scripts/build-app.sh` 发布构建和签名检查通过。

## 当前核验、历史跟踪缺口与权限说明

当前运行副本的核验结果与全局撤权确认分开报告。`runtimeRevisionState` 只描述已知
运行副本，`revisionState` 仍保留完整进程树的保守判断。界面列出副本、修订、已知 PID
和最近核验的代表进程；历史跟踪缺口不能被新副本检查通过所覆盖，也不能靠再次
重启当前程序清除。此前遗漏的子进程无法可靠重建，需保留提示；确认系统重启后，
旧启动周期的记录按已有逻辑清理。

不存在的正向授权目标改为“等待授权路径出现”，不再使整体核验一直等待。
不存在的拒绝目标（包括只读授权的写入限制）仍属于待核验，绝不视为已经拒绝。
已确认的差异优先报告，五秒周期继续检查路径出现、消失和访问结果变化。

旧规则的常见完整形式提供中文解释，原始文本放在高级页。组合、通配、未知规则
继续保留范围未确认提示；说明层不改写规则或撤权分析。旧规则保留的本机回环
端口绑定与接收权限，在权限清单和网络设置旁明确提示。系统基础规则说明为额外
的运行访问，不再把文件清单称作完整访问范围。

历史停止记录明确“已跟踪进程已退出”；已有历史记录不改写，通过界面补充范围
说明。“检查并恢复”改为“重新检查状态”；高级页区分配置模式和真实核验结果。
Helper 协议提升到 5，新增字段可兼容读取旧报告。

验证：497 项测试通过，1 项真实登录启动测试保持显式跳过。包含当前核验与历史
缺口并存、缺失正向/拒绝目标、路径出现后补查、停止历史、旧报告解码，以及未知
规则不被解释成已知窄范围的回归测试。真实 macOS 子进程测试同时覆盖缺失正向目标
可延后、缺失拒绝目标仍待核验。
